# PWA Architecture - Service Worker & Caching Strategy

## 🔧 PWA Implementation Details

This document explains the Progressive Web App (PWA) architecture implemented in the Workout Tracker, focusing on service worker configuration, caching strategies, and offline functionality.


## 🗂️ Caching Strategy

### Precache Strategy

```javascript
globPatterns: ["**/*.{js,css,html,ico,png,svg}"];
```

**Purpose**: Caches all static assets during service worker installation.

### Runtime Caching

#### 1. **HTML Files** (Navigation)

```javascript
{
  urlPattern: /\.html$/,
  handler: 'NetworkFirst',
  options: {
    cacheName: 'html-cache',
    expiration: {
      maxEntries: 10,
      maxAgeSeconds: 60 * 60 * 24 // 1 day
    },
    networkTimeoutSeconds: 3
  }
}
```

**Strategy**: Network First with 3-second timeout
**Use Case**: Page navigation and app shell

#### 2. **External Resources** (Fonts)

```javascript
{
  urlPattern: /^https:\/\/fonts\.googleapis\.com\/.*/i,
  handler: 'CacheFirst',
  options: {
    cacheName: 'google-fonts-cache',
    expiration: {
      maxEntries: 10,
      maxAgeSeconds: 60 * 60 * 24 * 365 // 1 year
    }
  }
}
```

**Strategy**: Cache First
**Use Case**: Static external resources

#### 3. **API Requests** (Future)

```javascript
{
  urlPattern: /^https:\/\/api\./,
  handler: 'NetworkFirst',
  options: {
    cacheName: 'api-cache',
    expiration: {
      maxEntries: 50,
      maxAgeSeconds: 60 * 60 // 1 hour
    },
    networkTimeoutSeconds: 5
  }
}
```

**Strategy**: Network First with 5-second timeout
**Use Case**: Dynamic data and API calls

## 🔄 Service Worker Lifecycle

### 1. **Installation**

```javascript
// Service worker installs and caches resources
self.addEventListener("install", (event) => {
  event.waitUntil(
    caches.open("v1").then((cache) => {
      return cache.addAll([
        "/",
        "/index.html",
        "/static/js/bundle.js",
        "/static/css/main.css",
      ]);
    })
  );
});
```

### 2. **Activation**

```javascript
// Service worker activates and cleans up old caches
self.addEventListener("activate", (event) => {
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames.map((cacheName) => {
          if (cacheName !== "v1") {
            return caches.delete(cacheName);
          }
        })
      );
    })
  );
});
```

### 3. **Fetch Interception**

```javascript
// Service worker intercepts network requests
self.addEventListener("fetch", (event) => {
  event.respondWith(
    caches.match(event.request).then((response) => {
      return response || fetch(event.request);
    })
  );
});
```

## 📊 Caching Strategies Explained

### **Cache First**

- Check cache first
- Only go to network if not in cache
- **Best for**: Static assets, fonts, images

### **Network First**

- Try network first
- Fall back to cache if network fails
- **Best for**: Dynamic content, API calls, HTML

### **Stale While Revalidate**

- Serve from cache immediately
- Update cache in background
- **Best for**: Frequently changing content

### **Network Only**

- Always go to network
- Never use cache
- **Best for**: Critical real-time data

## 🚀 Navigation Fallback

### Configuration

```javascript
navigateFallback: "/index.html";
```

### Purpose

- Handles client-side routing
- Serves `index.html` for all navigation requests
- Enables SPA behavior in PWA

### How It Works

1. User navigates to `/workout/123`
2. Service worker intercepts request
3. Serves cached `index.html`
4. React router handles client-side routing

## 🔧 Development vs Production

- Use for feature development

### Production Mode

- Full PWA functionality
- Service worker properly configured
- Use for testing PWA features

### 2. **Install Prompt**

- User clicks install
- Browser shows installation dialog
- User confirms installation

### 3. **Post Installation**

- App appears in app launcher
- Opens in standalone mode

## 📚 Best Practices

### 1. **Cache Management**

- Use appropriate cache strategies
- Implement cache versioning
- Clean up old caches

### 2. **Performance**

- Cache critical resources
- Optimize bundle size
- Use lazy loading

### 3. **User Experience**

- Show offline status
- Provide offline functionality
- Handle errors gracefully

- Implement CSP headers
